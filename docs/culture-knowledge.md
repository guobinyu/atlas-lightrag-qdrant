# 文化知识库

重启应用后进入 `?view=culture` 或左侧“文化知识库”。它是面向设计的解码库，与 CIDOC CRM 标准语义图谱并存：语义图谱记录史实，文化知识库记录纹样、配色、寓意和适用场景。

## 三层结构

- 主题层：预置婚恋、亲情、友情、校园校友、赛事活动、城市礼赠、节日纪念，可在“人工标注”中新增。新主题只用于之后创建的解码批次。
- 样本层：一份已保存资料（网页、上传或示例正文）。
- 素材层：文化IP、符号纹样、配色方案、文化内涵、消费场景、产品品类六类，关系为象征、适用场景、适配品类、搭配配色、源自IP，按类型约束校验。

每个素材标注依据：`documented`（资料记载）或 `interpretation`（设计解读）。文化内涵一律按设计解读处理。

## 解码

- “一键采集并解码”：复用语义图谱的检索词规划、公开搜索和正文读取（最多 10 份，每份前 9,000 字符），然后解码。
- “解码所选资料”：选择资料工作台中已有资料。
- 正文按约 3,000 字分块发送给已配置模型。素材和关系的引文必须能在原文定位（精确或近似）才入库；无法定位的引文、不符合类型约束的关系和未知主题记为“未入库提示”，不阻断整块。
- 同一类型下名称规范化后相同即合并，保留所有来源的引文；不做跨类型或语义合并。人工修改过的描述不会被后续解码覆盖。
- 失败或中断的文本块可以重试；模型、解码版本或正文变化后需新建批次。成功块不重复调用模型。

## 检索与接入方案

- 已发布素材写入独立 Qdrant 集合 `atlas_culture_<workspace>`，使用同一 bge-small-zh 向量，SQLite 为唯一真实来源。启动、解码结束、人工标注和检索时增量同步；集合缺失或不一致时自动重建。该集合不进入 LightRAG 检索、向量页或检索观察台。
- 产品候选生成时，除原有 K 片段外，按需求中的人群、场景、用途检索最多 8 个素材，作为 `M1`–`M8` 冻结在本轮资料中。需求包含婚礼、校友、伴手礼等词时先按对应主题过滤，不足再补充开放检索。
- 候选、需求单和设计方案的故事映射与配色项可以填写 `element_ref`。程序检查该编号存在于本轮资料；设计配色引用配色素材时 HEX 必须取自素材。
- `facts` 引用 M 素材时只能引用其原文引文；设计解读类素材不能作为事实。素材摘要（card）是模型或人工整理的文字，不是引文。
- 库中无匹配素材时页面提示，方案照常按创意建议生成。旧任务、旧候选和旧方案不改写。

## 人工标注与导出

- 可新增或编辑素材、添加关系、驳回或恢复素材。人工素材标记为“人工标注”，没有原文依据，不能作为事实引用。
- 导出 JSON（主题、样本、素材、关系、引文）和 JSONL（每行一个已发布素材），可作为标注或微调数据的起点；描述需人工抽查后使用。
- 数据位于 `data/workbench/<workspace>/culture/culture.sqlite3`。

## 验证

```sh
NO_PROXY=127.0.0.1,localhost .venv/bin/python -m pytest -q tests/test_culture.py tests/test_culture_ui.py tests/test_culture_integration.py
.venv/bin/python scripts/verify_culture.py   # 调用真实模型，可能产生费用
```

自动测试使用固定模型响应，覆盖协议校验、引文定位、合并、重试与重启、人工标注、增量索引、主题优先检索、需求与设计的素材引用校验及页面操作；集成测试使用真实本地 Qdrant 和 bge-small-zh。`verify_culture.py` 在临时工作区解码六份示例并输出统计，`visual_review` 保持 `pending`，需要人工检查解读质量。

## 边界与后续

- 本期只处理文本资料。图片样本、图形元素提取和图文混合检索留待二期，与设计智能体一并确定。
- 检索相关性由向量相似度决定，没有重排序；相似度不是事实置信度。
- 解码不代表文化解释准确，素材质量仍需人工抽查。
