# 产品需求探索（第一轮）

启动或重启原应用，进入 `http://127.0.0.1:8501/?view=demand`，或在左侧选择“产品需求探索”。升级时需重启服务，确保缓存的工作区加载新模块。现有热点营销、图谱和历史资料继续保留。

## 操作流程

1. 保存新任务：填写原始需求、行业、生产能力，选填品牌和已知限制。可明确复制历史任务的商家信息；不自动套用上次品牌，也不复制旧话题、候选和需求单。
2. 点击“开始完善需求”：分析完成后打开弹窗，每轮至多三个问题，逐题选择并填写补充说明，也可选择“暂不确定，请给建议”。保存下一题后可以关闭暂停，从“继续完善需求”恢复；未保存文字不保证刷新后保留。整轮提交才调用模型继续分析。
3. 点击“按当前需求继续”，在弹窗检查、编辑摘要和已保存回答。模型整理的人群、场景、主题只作为待确认建议，不覆盖原字段。点击“确认需求并继续”才进入资料阶段：近期话题路径搜索后等待选题；定制路径开放候选生成，不搜索热点，至少需填写人群、场景或主题之一。
4. 生成三个或五个候选。可填写调整意见生成新一轮，或从当前条件下的轮次选择一个产品方向。
5. 生成设计需求单，查看文化故事、设计建议、商家限制和参考资料。填写修改意见生成新版本，下载 Markdown 或 JSON 交给设计方。

生成时使用已配置模型。任务在后台运行，切换页面后继续；等待用户输入时不占用任务锁。服务需保持运行，同一工作区同时只执行一项检索或构建任务。

## 两条路径与依据

- 近期话题：默认最近 7 天，可选 24 小时或 30 天；最多三个检索词，每词十个候选链接，最多读取十份不同正文，每份分析最多 9,000 字符。日期核验、去重与公网抓取复用现有机制。
- 日期待核实或超出范围的话题只作为文化参考。所有话题均标“热度未验证”，公开搜索结果和时间核验不能证明传播热度。
- 搜索无可用正文时停在失败阶段，不虚构热点，也不自动切换路径。网络失败可重试；已成功但为空的搜索结果需要“重新搜索话题”获取新快照。用户也可编辑摘要改走定制路径。
- 定制路径仅检索本地文本。本轮不增加定制主题网页搜集、本体推理或自动补充长期知识库。
- 两条路径最多检索五个相关本地片段。无命中时如实提示，允许创意建议；技术错误则停止并允许重试。
- 用户提供的商家信息由程序保存，模型理解、能力匹配和产品建议单独展示，不能作为销量或生产可行性的保证。
- `facts` 仅允许引用当前资料的实际标识和可定位引文，用户需求不冒充外部文献。引用检查只证明来源存在、引文可定位，不证明语义蕴含、历史真实性或资料可靠性。本轮没有独立模型事实复核或专家评审。

## 保存与版本

每个任务保存在 `data/workbench/<workspace>/demands/<任务ID>.json`。包含用户输入、澄清、摘要版本、资料快照、话题选择、候选轮次、需求单和操作记录，JSON 格式版本为 1。写入使用临时文件替换；使用现有 `jobs/` 保存阶段、调用耗时与服务提供的 token 用量。

修改上游输入会生成新摘要版本，清除当前选择，并将旧候选和需求单标为历史条件；不删除旧成果。重新搜索会创建新资料快照，旧资料不用于新的选择。导出历史需求单使用其原始输入和证据，不混入当前已修改条件。

失败或中断不自动重发。显式重试复用已保存的模型阶段、正文和检索结果；无效输出保留检查错误，重试时将错误反馈给模型。若需求或选择已变化，拒绝重试旧操作，需按当前条件重新生成。远端模型调用与本地文件写入没有跨系统事务，返回后、落盘前崩溃仍可能导致重试重复调用。

仅支持现有单进程工作区方式；不新增商家账户、多人权限、自动营销交接、图片生成或外部发布。停止应用后备份整个工作区即可保留任务与相关来源。

## 验证与复现

```sh
NO_PROXY=127.0.0.1,localhost .venv/bin/python -m pytest -q tests
.venv/bin/python scripts/verify_demand.py --case both
```

真实验收命令使用当前模型连接、真实搜索和隔离的空本地知识库，所有任务写入临时目录，不修改生产任务。报告包含逐阶段状态、耗时和服务用量，成功后保存两版需求单及导出文件。运行该命令会调用模型服务；固定响应测试不代表真实生成质量。

### 2026-10-14 澄清轮次上限

每个需求任务最多进行 5 轮问答，每轮最多 3 个问题。首次分析负责提出第一轮问题；第五轮提交后的分析只整理摘要，不再生成第六轮问题，剩余问题转为待探索项。失败重试不新增轮次，修改摘要不重置任务额度。历史任务超过上限时直接进入确认，已有记录保留。达到上限后仍可人工编辑和确认摘要，不会自动批准或生成产品。
