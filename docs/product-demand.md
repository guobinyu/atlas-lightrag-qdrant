# 产品需求探索与设计图稿

启动或重启原应用，进入 `http://127.0.0.1:8501/?view=demand`，或在左侧选择“产品需求探索”。升级时需重启服务，确保缓存的工作区加载新模块。现有热点营销、图谱和历史资料继续保留。

## 操作流程

1. 保存新任务：填写原始需求、行业、生产能力，选填品牌和已知限制。可明确复制历史任务的商家信息；不自动套用上次品牌，也不复制旧话题、候选和需求单。
2. 点击“开始完善需求”：分析完成后打开弹窗，每轮至多三个问题，逐题选择并填写补充说明，也可选择“暂不确定，请给建议”。保存下一题后可以关闭暂停，从“继续完善需求”恢复；未保存文字不保证刷新后保留。整轮提交才调用模型继续分析。
3. 点击“按当前需求继续”，在弹窗检查、编辑摘要和已保存回答。模型整理的人群、场景、主题只作为待确认建议，不覆盖原字段。点击“确认需求并继续”才进入资料阶段：近期话题路径搜索后等待选题；定制路径至少填写人群、场景或主题之一，也结合近期热点：可先搜索选题，或生成候选时自动搜索并使用首个推荐话题。
4. 生成三个或五个候选，先比较用途、体验、区别及能力缺口，再查看故事到设计的对应关系。可填写调整意见生成新一轮，或选择当前条件下的一个产品方向；选择不表示已确认全部容量、材料和工艺。
5. 生成概念设计需求单，查看文化故事、具体设计建议、核心／可选交付及推进条件。辅助事项与来源默认折叠，Markdown、JSON 下载完整保留。填写修改意见生成新版本，交给设计方试用。
6. 在“5 · 设计方案”确认来源需求单版本，点击“生成设计方案”。查看整体概念、视觉设计、产品应用与交付，填写修改意见生成设计方案新版本；可独立下载设计方案 Markdown、JSON，原需求单保持不变。
7. 在“5 · 设计方案”生成或修订方案时，配置图片服务后会自动为第一个核心应用生成三版方形图稿。文字方案和已完成图片逐项保存，失败可重试补齐。也可在同一步的“设计图稿”中选择其他应用项和像素规格补充生成；选用一张后填写修改意见，基于原图生成新版本。图片按来源设计版本和应用项隔离展示，可切换历史批次、放大查看并下载 PNG。

生成时使用已配置模型。任务在后台运行，切换页面后继续；等待用户输入时不占用任务锁。服务需保持运行，同一工作区同时只执行一项检索或构建任务。

## 两条路径与依据

- 近期话题：默认最近 7 天，可选 24 小时或 30 天；最多三个检索词，每词十个候选链接，最多读取十份不同正文，每份分析最多 9,000 字符。日期核验、去重与公网抓取复用现有机制。
- 日期待核实或超出范围的话题只作为文化参考。所有话题均标“热度未验证”，公开搜索结果和时间核验不能证明传播热度。
- 搜索无可用正文时停在失败阶段，不虚构热点，也不自动切换路径。网络失败可重试；已成功但为空的搜索结果需要“重新搜索话题”获取新快照。两种路径均不能绕过来源检查编造热点。
- 定制路径围绕人群、场景、用途及文化主题搜集近期热点正文，并结合本地文本；热点不替换已确认的人群和场景条件。不新增本体推理或自动补充长期知识库。
- 两条路径最多检索五个相关本地片段。无命中时如实提示，允许创意建议；技术错误则停止并允许重试。
- 用户提供的商家信息由程序保存，模型理解、能力匹配和产品建议单独展示，不能作为销量或生产可行性的保证。
- `facts` 仅允许引用当前资料的实际标识和可定位引文，用户需求不冒充外部文献。引用检查只证明来源存在、引文可定位，不证明语义蕴含、历史真实性或资料可靠性。本轮没有独立模型事实复核或专家评审。

## 保存与版本

每个任务保存在 `data/workbench/<workspace>/demands/<任务ID>.json`。包含用户输入、澄清、摘要版本、资料快照、话题选择、候选轮次、需求单、设计方案和操作记录，外层 JSON 格式版本为 1。设计方案保存在可选 `design_versions` 列表中，使用独立内容格式版本 1；旧任务缺省为空，不批量改写。写入使用临时文件替换；使用现有 `jobs/` 保存阶段、调用耗时与服务提供的 token 用量。

修改上游输入会生成新摘要版本，清除当前选择，并将旧候选和需求单标为历史条件；不删除旧成果。重新搜索会创建新资料快照，旧资料不用于新的选择。导出历史需求单使用其原始输入和证据，不混入当前已修改条件。

失败或中断不自动重发。显式重试复用已保存的模型阶段、正文和检索结果；无效输出保留检查错误，重试时将错误反馈给模型。若需求或选择已变化，拒绝重试旧操作，需按当前条件重新生成。远端模型调用与本地文件写入没有跨系统事务，返回后、落盘前崩溃仍可能导致重试重复调用。

仅支持现有单进程工作区方式；不新增商家账户、多人权限、自动营销交接或外部发布。图片生成功能需单独配置，未配置时文字功能仍可使用。停止应用后备份整个工作区即可保留任务与相关来源。

## 验证与复现

```sh
NO_PROXY=127.0.0.1,localhost .venv/bin/python -m pytest -q tests
.venv/bin/python scripts/verify_demand.py --case both
.venv/bin/python scripts/verify_demand.py --intake
.venv/bin/python scripts/verify_demand.py --design
.venv/bin/python scripts/verify_design_proposal.py
```

真实验收命令使用当前模型连接、真实搜索和隔离的空本地知识库，所有任务写入临时目录，不修改生产任务。报告包含逐阶段状态、耗时和服务用量，成功后保存两版需求单及导出文件。运行该命令会调用模型服务；固定响应测试不代表真实生成质量。

`verify_design_proposal.py` 直接导入 `docs/demand-design-evaluation.json` 中第二阶段的真实需求单快照，在隔离工作区验证设计生成与修订，不重跑搜索、候选或需求单生成。支持 `--case custom`、`--case silk-custom`，以及 `--sources` 指定同格式案例记录。结果保留来源、版本和 Markdown／JSON 文件；网络错误或无效输出会记录失败，不自动重试。

### 2026-10-17 平面概念图稿生成与编辑

**配置与使用**

- 重启应用后，进入“模型设置 → 图片生成模型”。填写 服务商（默认火山引擎豆包 Seedream）、API 基础地址（默认 `https://ark.cn-beijing.volces.com/api/v3`）、模型（默认 `doubao-seedream-5-0-lite-260128`）、图片 API Key 和超时（默认 300 秒）。Seedream 生成与修改均调用 `/images/generations`；修改时在 JSON 的 `image` 字段传入原图 Base64。OpenAI 历史配置仍使用其原生成/编辑端点。
- “保存图片配置”只校验格式，不调用模型；“生成测试图”实际调用图片接口并产生费用。测试图在后台生成，切换页面不重发。模型名称可修改，但应使用支持 PNG/base64 输出和当前请求参数的模型或推理接入点。Seedream 默认 5.0 lite；4.5/4.0 不支持同样的 PNG 输出参数，不能只改模型名使用。
- 图片密钥独立保存在工作区 `image-settings.json`，文件权限 600；不复用文字服务密钥，更换地址且不填新密钥时会清空。任务快照不保存密钥。
- 每次选择一个具体应用项，默认第一个核心应用。Seedream 图稿提供方形 2048×2048、横向 2496×1664、纵向 1664×2496，使用模型默认质量、PNG 输出和 AI 生成水印；不发送 OpenAI 的 `quality` 或 `n` 参数。OpenAI 历史服务保留原 1K 规格和 medium 质量。这些像素规格不代表产品生产尺寸。
- 文字模型整理三个构图要求，然后逐张生成；选用和查看不调用模型。修改会把原图及冻结的要求发送至图片服务，生成一张新图；修改不改写文字方案。继续修改新版时先明确选用新版。

**保存、恢复与边界**

- 任务新增可选 `image_assets` 和 `image_selections`；旧任务缺省为空，无批量迁移。原有任务格式版本保持 1。生成操作冻结文字设计版本、应用项、图片模型配置和原图，资产保存于 `demands/assets/<任务ID>/`，任务 JSON 保存相对路径及摘要。
- `demand_image_generate` / `demand_image_revise` 接入已有锁、进度与 `demand_retry`。每张成功后立即保存，部分失败只补未完成项；已保存提示词不重复整理。图片修改与已缓存提示词的补生成不依赖文字模型连接。
- 上游条件或产品选择变化后，历史图稿仍可查看、下载，不能直接修订。切换文字方案时只显示对应图稿。图片接口地址改变后不向新地址转发旧任务凭证：恢复原地址重试，或按新配置重新生成。
- 图片输出检查格式、可读性与大小，不做审美或文化真实性自动验收。首版仅生成平面概念稿，无外部参考图上传、效果图、矢量稿、分色或生产文件。
- 每次三图生成涉及一次文字模型调用和三次图片调用；每次修订涉及一次图片调用。服务端响应后、本地保存前中断，或请求超时，可能已经计费；显式重试可能再次计费。
