# 热点营销工作台

使用原有启动方式，进入 `?view=campaign` 或点击左侧“热点营销”。默认采用演示模式，使用公开搜索发现话题；日期与匹配结论作为提示，不阻断完整方案生成。不提供平台热榜，也不把来源数量当作热度或独立证据数量。

## 使用流程

1. 在“模型设置”配置可用的 Chat Completions 兼容模型。
2. 只需输入营销需求，例如“帮我搜索一下近期的热点信息并设计营销传播方案”。无需填写或确认品牌名称、产品卖点和目标人群。
3. 时间范围默认最近 7 天，可选 24 小时或 30 天。营销目标默认品牌曝光；渠道、预算可留空。执行周期默认 7 天（独立于搜索时间范围），示例预算 3 万元，默认选择两个渠道；用户明确条件优先。
4. 点击“搜索并生成方案”。系统先搜索与核验话题，再结合热点和知识库自动推理品牌名称、产品方向、卖点、人群、定位、场景和表达边界，直接继续匹配与生成。任务在后台执行，页面切换不重复提交。所有时间按北京时间展示。
5. 左侧选择话题，右侧查看营销方案、执行安排、推荐依据。优先为推荐话题自动生成初稿，没有推荐时从现有候选继续；其他话题均可点击生成，包括旧任务中日期待核实的话题。
6. 选择历史版本，输入调整要求生成新版本。旧版本和原始资料快照保留；重新搜索会创建新任务。可以下载 Markdown 和 JSON。
7. 搜索没有可用话题或采集全部失败时，自动生成“常规内容建议（非热点）”作为演示，页面保留搜索失败说明，不编造近期新闻。也可随时单独生成常规建议。

“为此话题生成方案”在模型已配置且工作区空闲时开放。点击后自动补齐品牌推理、话题匹配和完整方案。日期缺失、超出搜索范围、关联较弱都只作提示；查看推荐依据不需要确认，也不是前置步骤。

## 展示与导出

“营销方案”展示概览、策略、主题与可直接使用的图文/脚本；每份内容右上角有原生复制按钮。“执行安排”用表格展示排期、预算和目标。“推荐依据”展示折叠的来源与知识库资料。任务详情默认折叠，完成的方案突出“方案已生成”；部分采集失败只作资料提示。

新版 Markdown 按阅读顺序导出正文、执行表格和来源附录，附录不再输出原始 JSON 数据块；JSON 保留完整版本、输入和来源快照。旧版导出格式保持兼容。

## 证据与边界

- 最多三个检索词，每词十个候选；最多读取十份不同正文，每份用于分析的正文最多 9,000 字符。继承公网抓取的 URL/IP 校验、4 MB 文件限制及登录/反爬限制。
- 记录发布时间、事件时间、采集时间，保留页面元数据和原文日期引文。事件日期优先；缺少事件日期时明确仅按发布时间核验。采集时间不能证明是近期事件。
- 目前程序识别包含年份的 ISO、横线、斜杠和中文年月日日期。相对日期、没有年份或无法定位引文的日期保守标为待核实；日期精度跨越筛选起点时标为待核实。演示模式仍使用这些资料作为创意参考，不宣称已核实为近期热点。
- URL/正文去重后由模型聚合事件；同正文的其他链接保留为来源别名。不同正文仍可能是转载，界面只标“不同正文”，不宣称独立核实。
- 品牌推理与话题匹配各检索当前工作区最多五个相关片段。已有明确品牌线索时优先利用；没有线索时，根据收集到的话题自动提出策划品牌名称和产品方向，不要求用户补充。
- “自动推理的品牌与产品”区域展示逐项结果，分为“资料提取”和“策划推断”，附推理理由及引文。引用仍检查原文定位。演示模式将生成的品牌信息作为策划设定使用，省略额外的模型事实复核，不设置人工确认步骤。
- 推断的品牌名称与卖点可用于创意方案，但不表示品牌真实存在、已注册或产品已经具备相应属性。原文引用使用 S（网页）、I（品牌推理知识）、K（话题知识）标识，自动品牌设定 B1 不能自证为事实；方案事实必须引用原始资料。
- 新版演示方案使用 content_version=2：概览、核心策略、主题、两篇完整图文、一条至少三个镜头的视频脚本、逐日排期、预算分配、数字目标与调整动作、集中策划假设。主文不逐段标记判断/创意或引用编号；资料保留在推荐依据。只检查展示完整性、内容作品排期对应和预算合计，自动补全最多一次。失败保留草稿和“继续完善”，不额外调用模型事实复核。内部 mode=strict 保留原严格流程。
- 用户需求、相关网页正文和知识库片段发送到已配置模型；不保存模型隐藏思维链，错误消息沿用密钥脱敏。
- 不自动发布内容、不承诺传播效果、不接入付费投放。热点正文不自动写入长期 LightRAG 或本体图谱。

## 保存与恢复

`data/workbench/<workspace>/campaigns/` 下的任务 JSON 保存输入快照、搜索结果、正文、日期核验、自动推理的品牌与产品资料、逐项依据、品牌匹配、操作阶段和不可覆盖的方案版本。品牌推理成功后保存结果，下游重试与方案修订不重复推理或覆盖。新任务不读取或写入旧 `brand.json`，也不会静默套用上次的品牌信息；旧版任务与简档仍可查看、导出及修订。旧方案可点击“生成新版演示方案”，复用原资料生成新版本；不迁移或覆盖旧版本。复用原有 `jobs/` 保存真实模型调用事件、耗时与服务返回的 token 用量。写入采用临时文件替换，原有资料无需迁移。

同一工作区继续使用已有任务锁。品牌检索在任务内部异步调用，不会重复获取锁。各阶段成功结果及时保存；网络或模型失败后从失败阶段重试，不重复已保存的抽取、匹配或生成。进程重启只标记中断，不自动调用模型。结果部分完成时保留资料缺口，重新搜索可尝试补齐。文件写入与远端模型调用无法形成跨系统事务，因此进程恰好在模型返回但结果落盘前退出时，重试可能再次调用该步骤。

旧版日期校验可能误判空日期对象、正文带时分秒而模型只返回年月日、或引用页面发布时间元数据的情况。已有任务可点击“重新核验日期并继续”：复用原始资料与原搜索时间范围，创建新的派生任务，再自动推理品牌、匹配并为推荐话题生成方案。原任务和方案版本保留，不重新搜索或抓取网页；后续品牌与方案处理仍会调用已配置模型。演示模式不要求先执行重新核验，直接选择话题生成即可；日期状态仍如实保留。
