# 标准语义图谱使用与维护

Atlas 新增独立的 CIDOC CRM 7.1.3 语义流程：资料 → 模型抽取 → 本体校验 → 模型证据检查 → 自动发布。资料工作台现已提供主题驱动的一键搜集构图入口。原 LightRAG 图谱、向量存储和 naive 文本检索保持原路径，既有图谱不会自动迁移。

## 启动与使用

已有环境需先更新依赖，然后重新启动 Streamlit：

```sh
.venv/bin/python -m pip install -r requirements.lock.txt
./start.sh
```

1. 模型设置页配置并测试抽取模型。语义流程使用同一 HTTP/Ollama 连接，不要求服务商结构化输出选项。
2. 在自动构建入口输入主题、1–10 份数量及领域（默认通用文化），也可勾选已有资料执行手动构建。手动每批正文不超过 100,000 字符。`processed` 资料也可以首次进行语义抽取。
3. 每个有本地合格陈述的文本块额外调用一次模型证据检查；仅 supported 且本体校验通过的陈述自动发布，无需人工确认。
4. “抽取结果”展示全部输出及证据；“校验报告”展示未发布原因，可点击“重新校验并自动发布”。校验失败的陈述不影响同一块中合格陈述发布。
5. “已发布图谱”显示有向关系；同一实体对的多谓词以多行标签呈现，独立陈述可在下拉明细中分别检查。图限制 80 条陈述以控制绘图成本，导出包含全部正式数据。
6. 按领域、实体类型、来源和批次筛选。下载 Turtle、JSON-LD，或 JSON 审计包。撤回保留审核及发布历史，不再输出正式三元组；JSON 审计包的 `withdrawals` 专门保存撤回历史。
7. “校验报告”查看失败文本块、待建模概念和候选错误，可显式重试失败或中断块。成功块不重发；正文、模型设置或版本变化时必须新建批次。新批次独立抽取和校验。

所有字符偏移均为 Python Unicode 字符的半开区间 `[start, end)`，不是 UTF-8 字节或 JavaScript UTF-16 单元。

2026-10-06 起按用户要求采用宽松定位（`approximate-v1`）：模型的 start 仅作参考，先在原文块搜索完整引文，再忽略空格、换行与标点匹配；仍未匹配时，对至少 8 个有效字符的引文采用文字相似度不低于 85% 的近似片段。多处完整匹配时选择离模型位置最近的一处（没有位置则选第一处），并显示多处匹配提醒。不相近的内容仍不通过。

近似匹配不代表含义一致或事实可信。页面显示模型引文和实际原文、证据检查结论。保留抽取输出、原位置、匹配方式、相似度、实际片段及重新定位历史。“重新校验并自动发布”不额外调用模型，也不能绕过证据检查：仅已有当前 supported 结果的候选可以发布。历史未发布候选需重新抽取；已发布、驳回和撤回记录不被批量重写。

## 能力问题与建模范围

| 要回答的问题 | 建模路径 |
| --- | --- |
| 某次生产由谁实施？ | E12 → P14 → E21/E74（经 E39 继承） |
| 活动在哪里、何时发生？ | E7/E12 → P7 → E53；E7/E12 → P4 → E52 |
| 生产使用了什么材料，得到什么器物？ | E12 → P126 → E57；E12 → P108 → E22 |
| 器物由什么材料组成？ | E22 → P45 → E57 |
| 活动采用哪种技艺或具体规程？ | E7/E12 → P32 → E55；E7/E12 → P33 → E29 |
| 某一文献记载了什么？ | E31 → P70 → 允许的实体类型 |
| 器物或活动属于什么类型？ | E1 子类 → P2 → E55 子类 |

`lab/ontology/profile.py` 是类型、标准 URI、祖先关系、谓词两端约束、中文名称、规则和三领域小词表的唯一配置源。运行时不下载本体。依据 [CRM 7.1.3 官方类与属性定义](https://cidoc-crm.org/html/cidoc_crm_v7.1.3.html)，保存应用涉及的祖先闭包；没有加载整个 CRM 或启用推理服务。

- E22 是具体器物，器物类型为 E55。E55 也用于一般技艺；E29 是明确的设计或操作规程。
- E4 为时期，E52 为时间范围。E31/E33 表示文献或语言内容，不表示纸张、书册等物理载体。
- 只有确切一次活动才使用 E7/E12，并要求 `concrete: true`。这项声明来自模型，不能自动证明正文确实记载该活动；系统不提供事实真实性保证。
- P2 不能替代 P127 等上下位关系。未启用的类型/谓词及象征、意象、文化基因等解释性内容进入 `deferred`，不进入正式图谱。
- 当前全部启用谓词都是对象属性。协议可表示带 datatype 的字面量，但这些谓词使用字面量宾语会校验失败。
- 合法 E55 新概念可作为局部实体；只有固定词表 URI 才跨来源复用。普通实体在批次、来源和块内分配 ID，不按名称合并。重叠块可能生成不同候选，第一版不提供跨块或跨文档自动消歧。

2026-10-09 起自动发布增加模型证据检查门槛。工作区启动不会为历史候选补造新检查结果；只处理成功文本块、本体合格且证据检查 supported 的当前候选。历史已发布记录保留原依据，已驳回或已撤回记录不会复活。单块候选保存、状态更新和自动发布在同一 SQLite 事务内完成。

## 实现与持久化

```text
collect_page → SemanticService.start_extraction / Workspace.start
  → Engine.gate → Job + create_batch
  → 按段落分块（最多 3000 字符，重叠最多 300）
  → ExtractionLLM.extract_semantic → 既有 HTTP 封装
  → parse_response → 引用/白名单/证据定位 → RDFLib + SHACL
  → ExtractionLLM.verify_semantic → 批量模型证据检查
  → SQLite pending 候选
  → 自动校验与发布事务 → publications
  → get_published_graph / export
```

工作区文件：`data/workbench/<workspace>/ontology/semantic.sqlite3`。`PRAGMA user_version=1` 标记初始迁移，未来版本须增量迁移；较新数据库版本会被旧程序拒绝打开。数据库包含：

- `metadata`：稳定项目 URI，由随机 UUID 派生；无需拥有公网域名，不保证 URI 可通过 HTTP 访问。
- `batches`：领域、模型公开配置、CRM/提示词/应用配置版本与哈希、来源全文快照和哈希。
- `chunks`：来源、原文范围、处理状态、失败信息、成功 JSON（含待建模候选）。
- `entities`：候选实体；非受控实体 ID 在同一块重试中稳定。
- `candidates`：独立陈述与证据、实体快照、来源全文、版本、校验结果和审核状态。JSON 字段作为版本化记录保存，未拿 LightRAG keywords 充当谓词。
- `reviews`、`publications`：只追加审核与发布记录；撤回增加审核记录并设置 revoked_at。新自动记录 action=auto_publish、reviewer=系统自动发布、policy=automatic-evidence-v2、confirmed_types=false。历史人工审核记录保留。

每次数据库操作使用独立连接；写事务确保批量发布原子性，同一候选只能有一个有效发布记录。启动时将运行中批次/块标为中断，不自动调用模型。任务复用现有互斥锁和事件日志，失败不修改资料的 LightRAG 状态。模型失败或非法 JSON 只影响对应块；合法 JSON 中不合格陈述保留供查看，不自动向模型请求修复。

Turtle/JSON-LD 包含正式三元组、实体类型、标签以及 RDF Statement 重述，用稳定陈述 URI 关联独立证据、模型检查和审核记录。导出标注 CRM、本体配置、配置哈希及格式版本。JSON 审计包包含正式陈述与撤回历史的来源全文快照，不包含未发布或已驳回候选。

```sh
  --output /tmp/semantic-live-evaluation.json
```

`tests/fixtures/culture_samples.py` 含每领域 10 条、共 30 条合成核对样例及预期判断。它们是工程测试样例，不是文化史证据，也尚未获得独立领域专家的人工签字。不得把固定模型测试当成真实模型效果证明。真实评估另见 `docs/semantic-evaluation.md`。

## 当前边界

- SHACL 证明类型及属性形式符合配置，引文匹配提供原文参考位置；两者都不能证明事实正确、句子蕴含关系、材料来源可靠或模型没有歪曲含义。
- 不支持多人审核身份、自动消歧、编辑修复、历史版本重推理或语义图谱问答。驳回/撤回后的重建需新批次，不自动继承结论。
- 第一版按单进程运行；不要让多个应用进程同时打开同一工作区。备份应在停止应用后复制整个工作区（含 SQLite 与来源文件）。
- 合成样例覆盖有限；在批量处理真实文化材料前，仍需领域人员核对样例、本体映射与实际输出。
